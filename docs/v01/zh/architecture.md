# 架构说明

<span class="manual-label">维护者资料 · 不是接入前置</span>

扩展库之前先阅读[用户路径](quick-start.md)。BatchQueue 只有一个公开入口和一套 Redis 状态机，存储、运行时类不作为包子路径提供。

## 模块边界

| 模块 | 职责 |
|---|---|
| 根入口与 Batch API | 显式公开导出、类型和稳定错误 |
| 领域模块 | 严格 JSON/配置、任务身份、上下文控制值和游标 |
| 应用层 | 接收任务、查询与控制编排 |
| 运行时 | 本地物理槽、租约、协作执行、回调与关闭 |
| Redis 存储 | 显式 key 计划、静态 Lua、预算与有限索引 |

唯一运行依赖为 `@redis/client@6.1.0`。应用仓储、外部服务和框架托管不属于包实现。

## 原子边界

状态提交在 Redis 操作内检查当前租约、token 和 revision。旧执行不能推进 Run，但撤销提交权限不能撤回已发生的外部写。容量预留覆盖结算和 Event 创建；依赖解除后 GC 才归还计费。

## 生命周期

导入、构造和定义没有网络 I/O。`ready()` 持有连接并启动选定模式。`close()` 停止接收/领取并在本地宽限期内等待；尚未退出的 handler 继续占物理槽。

## 验证

参考[验证与发布边界](development-contract.md)。内部测试可隔离构建模块；分发测试必须打包、独立安装实际根包，不使用仓库路径别名。
